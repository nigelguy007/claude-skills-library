# Problem Framing and Issue Diagnosis

## When to use

Use this skill at the start of any strategy engagement, when a sponsor hands you a
broad question ("grow the business," "fix declining margins," "should we enter this
market") and the team has not yet agreed on the real, answerable problem underneath it.
It is also useful mid-engagement whenever analysis stalls because the team is chasing
hypotheses that do not actually address the sponsor's real concern.

## Instructions

1. Restate the sponsor's question as a single, specific, answerable problem statement.
   Flag any ambiguity in scope, timeframe, or success definition before proceeding.
2. Build a MECE issue tree that breaks the problem statement into 3 to 5 top-level
   branches. Confirm branches do not overlap and collectively cover the full problem.
3. Under each branch, draft 2 to 4 testable hypotheses phrased as falsifiable claims,
   not questions (for example "Margin decline is driven by mix shift, not price").
4. For every hypothesis, name the smallest piece of evidence that would prove or kill
   it, and flag whether that evidence is already available or needs to be gathered.
5. Rank all hypotheses by expected impact on the problem statement and ease of testing.
   Produce a top-5 shortlist the team should chase first.
6. Write a one-paragraph framing summary a sponsor could read in 30 seconds: the
   problem statement, the branches, and the top-priority hypotheses.

## Example prompts

- "Use the problem-framing-diagnosis skill on this brief: the CEO wants a plan to
  'improve profitability' next year but hasn't defined what's driving the shortfall.
  Here's the background: [paste notes]."
- "Run problem-framing-diagnosis on this situation: two business units disagree on
  whether the growth problem is a demand problem or a go-to-market problem. Build the
  issue tree that separates the two hypotheses cleanly."
- "Use this skill to frame the real question behind a request to 'evaluate whether we
  should exit this product line,' given this context: [paste context]."

## Output

A structured framing memo with four parts: the restated problem statement, the MECE
issue tree (branches and sub-hypotheses), the evidence plan for each hypothesis (what
would prove or kill it, and whether that evidence exists yet), and a ranked top-5
shortlist of hypotheses to test first, with the one-paragraph sponsor summary at the top.
