# Execution and Operating Model Design

## When to use

Use this skill once a strategic option has been chosen and the team needs to translate
it into something that can actually be built and run: who owns what, what changes in
the organization, and in what sequence the work happens. It is the handoff point from
"what we decided" to "how it gets done."

## Instructions

1. Restate the chosen strategy and the outcome it is meant to deliver, so the operating
   model and roadmap stay anchored to the actual decision, not a generic template.
2. Define the operating model changes required: what new capability, team, process, or
   decision right needs to exist that does not exist today. Keep this to the changes
   that are actually load-bearing for the strategy, not a full org redesign.
3. Break the rollout into 3 to 5 phases (for example: pilot, scale, steady-state).
   Define the entry and exit criteria for each phase, not just a date range.
4. For each phase, list the key milestones, the owner accountable for each one, and any
   dependency on another phase, team, or external factor.
5. Build a lightweight RACI for the 4 to 6 highest-stakes decisions or workstreams in
   the plan, so accountability is explicit before execution starts.
6. Flag the two or three execution risks most likely to derail the timeline, and the
   mitigation or early-warning signal for each.

## Example prompts

- "Use the operating-model-execution-plan skill to build a phased rollout plan for
  [chosen strategy], including a RACI for the top workstreams."
- "Run this skill on this decision to move to a new go-to-market model, and define
  what changes in the operating model versus what stays the same: [paste context]."
- "Use operating-model-execution-plan to turn this one-page strategy into a
  pilot-to-scale roadmap with named owners and phase exit criteria."

## Output

An execution plan with four parts: the required operating model changes, a phased
roadmap with entry and exit criteria per phase, a milestone and owner list with
dependencies flagged, and a RACI table for the highest-stakes decisions, closing with
the top execution risks and their mitigations.
